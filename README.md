# isct-pbc-2026-team-starter

[English](README.en.md)

東京科学大学 プログラミングブートキャンプ 2026 のラーニングフェーズ4回目で使う、チーム開発のスターターです。
題材を持たない「項目（item）」の一覧・詳細・追加と、AI 機能の例が1つだけ入っています。チームの題材に置き換えて使います。

依存パッケージはありません。Node.js 24 以上だけで動きます。

## 動かし方

```bash
npm start
```

ブラウザで http://localhost:3000 を開きます。止めるときはターミナルで Ctrl+C。

`npm start` は `node --env-file-if-exists=.env server.js` と同じです。初めて起動すると `data.db` ができ、見本の項目が3つ入ります。

起動したときに次の2行が出ることがありますが、問題ありません。

- `.env not found. Continuing without it.`（`.env` をまだ作っていない。AI 機能はモックで動く）
- `ExperimentalWarning: SQLite is an experimental feature ...`（Node.js 標準の SQLite が「試験中」の扱いであるという知らせ）

## テスト

```bash
node --test
```

`test/` の下のテストを動かします。テストは実際の Gemini を呼びません。

## AI 機能（Gemini）

キーが無いうちは、AI 機能はモックの応答で動きます。画面と流れはモックのまま作れます。

実際の Gemini で試すとき:

1. Google AI Studio（https://aistudio.google.com/apikey）でキーを取る（個人の Google アカウントで）
2. `.env.example` をコピーして `.env` を作り、`GEMINI_API_KEY=` の後ろにキーを書く
3. サーバーを起動し直す

注意:

- `.env` はコミットしません（`.gitignore` に入っています）。キーはチームで共有せず、各自の `.env` に各自のキーを置きます。
- 無料枠には上限があります（1分あたり・1日あたりの回数）。上限に達すると「上限に達しました」と出ます。少し待つか、`.env` のキーを消してモックで続けます。
- 無料枠に送った入力と出力は、Google が製品改善に使います。個人情報や秘密を送らないでください。

## ファイルの構成

| 場所 | 中身 | 誰が触るか |
|---|---|---|
| `features/` | 機能ごとに1ファイル（画面と API）。新しい機能はここにファイルを足す | 機能の担当者 |
| `shared/nav.js` | 画面の上のナビ。機能を足したらリンクを1行足す | 全員（コンフリクトが起きやすい） |
| `lib/` | 全員が使う道具（DB、HTML、HTTP、Gemini の呼び出し） | 直すときはチームに一言 |
| `public/style.css` | 見た目 | 誰でも |
| `test/` | `node --test` で動くテスト | 機能の担当者 |
| `server.js` | `features/` を読み込んで動かす入り口。ふだんは触らない | |
| `CLAUDE.md` | チームの約束ごと。空欄をチームで埋める。英語で進めるチームは `CLAUDE.en.md` の中身に置き換える（Claude Code が自動で読むのは `CLAUDE.md` だけ） | 全員（PR で） |
| `.claude/settings.json` | Claude Code に触らせないもの（`.env` の読み取り、main への push など） | |
| `.claude/skills/write-pr/` | 「PR を書いて」と頼んだときのやり方 | |

## 題材の例（迷ったら）

題材はチームで自由に決めてよいです。条件は3つです。

1. 開発フェーズ（合宿）で作るものとは別のもの
2. 自分たちが使いたい・作りたいもの
3. 2時間で1人1機能を足せる小さなもの

迷ったら、次から選んで自分たちに合わせて変えてください。どれも「項目（item）」を置き換えるだけで始められます。1人1機能の分け方は一例です。AI 機能は少なくとも1つ入れます（いくつあってもかまいません）。

| 題材 | 項目にあたるもの | 1人1機能の例 |
|---|---|---|
| 研究室・サークルの落とし物掲示板 | 落とし物（何を・どこで・いつ） | 場所で絞り込む／「持ち主が見つかった」の印／見つけた日の新しい順に並べる／AI で説明から特徴のタグを付ける |
| 部室の観葉植物の水やり帳 | 植物（名前・置き場所・最後に水をやった日） | 水やりを記録するボタン／何日あげていないかの表示／水やり当番の担当者／AI で育て方のひとことを出す |
| 共有の買い出しリスト | 買うもの（品名・数・誰が頼んだか） | 「買った」の印／頼んだ人で絞り込む／買った物を下に回す／AI で頼まれた物を売り場ごとにまとめる |
| おすすめ作品の共有リスト（映画・アニメ・ゲーム） | 作品（タイトル・種類・ひとこと） | 星で評価／種類で絞り込む／「見たい」の印と人数／AI でネタバレなしの紹介文の下書きを作る |
| 研究室の質問箱 | 質問（内容・誰向けか・答え） | 答えを書く欄／「答えあり・なし」で絞り込む／「私も知りたい」の数／AI で似た質問がもうないかを探す |

## 合宿でチーム開発を始めるための準備について（任意）

4回目で練習した進め方を、合宿用のチームのリポジトリにも入れておくと、合宿で始めやすくなります。4回目の講義の中では作りません。やるかどうか、いつやるかはチームで決めてください。もう開発を進めているチームは不要です。

入れる場合は、この練習のリポジトリから、題材にも技術にもよらないものだけを Claude に写させます。

| 写すもの | 写し方 |
|---|---|
| `CLAUDE.md`（または `CLAUDE.en.md`）の「開発ルール」の部分 | そのまま写す。「何のアプリか」の部分は見出しだけ残し、中は空欄にする（何を作るかを 12/12 に全員で決めてから埋める） |
| `.claude/settings.json` | そのまま写す。`data.db` の2行は、合宿で使うデータのファイル名に変える（無ければ消してよい） |
| `.claude/skills/write-pr/` | そのまま写す |
| `.gitignore` の `.env` の行 | `.env` をコミットしないための行だけ写す（技術を決めたら、その技術の行を足す） |
| README のチームの約束 | レビューは誰がするか、main に入れる条件など、チームで決めたことだけを書く |

コード（`features/`、`lib/`、`server.js` など）、`package.json`、`.env.example`、`data.db` は写しません。技術スタックは 12/12 以降に決めます。

## 機能の足し方

1. ブランチを切る（例: 「`add-deadline` というブランチを切って」と Claude に頼む）
2. `features/` に新しいファイルを作り、`routes` を書き出す（`features/item-detail.js` が見本）
3. `shared/nav.js` にリンクを1行足す
4. 手で確かめ、テストを足し、PR を出す（「PR を書いて」）

最初の1機能に迷ったら、編集や削除から始めてください。スターターには一覧・詳細・追加しか入っていないので、どの題材でも要る機能です。どちらも詳細の画面にボタンを足すので、同じファイルを触ってコンフリクトを直す練習にもなります。削除は「確認を出すか」「消したあとどこに戻るか」「もう無い項目を消そうとしたら」など、確かめる観点を書き出す練習にも向いています。
